Know why the code is like this.

Other tools tell you what the code says. CodeWhy tells you why it's that way, whether that reason still applies, and when it can't tell, it says so.

How it works

1
Read the historyCodeWhy reads a repo's commits, pull requests and issues, then links them to files.
2
Build an evidence graphOnly explicit links count as verified, such as "#41", a URL, "fixes" or a revert line. Everything else is labeled.
3
Answer with sourcesEvery sentence cites evidence you can click. No evidence means no answer.

Four questions you can ask

Why is it like this?The reason, with the commits, PRs and issues behind it.
How did it change?A timeline from the original change to later ones.
Is it still needed?A drift check that says "Possibly outdated. Verify."
Code DNAOrigin, key decisions and files that change together.

Honest labels

verifiedExplicit in the source.
inferredOur heuristic, not stated.
heuristicA signal to double-check.
unknown"Insufficient evidence in the repository."

Based on repo history only, not a prediction. The demo works on repos fetched in advance.
